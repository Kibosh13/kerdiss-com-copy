# Развёртывание CMS

Сервер: PHP 8.4 с PDO SQLite, SQLite3, mbstring, GD и WebP. Поддерживается SQLite старых версий без UPSERT и VACUUM INTO. Для сборки интерфейса нужен Node.js 22.12+; на хостинге Node.js не требуется.

## Локальный запуск

```sh
npm ci
npm run build
php scripts/admin.php create admin@example.com "Администратор"
npm start
```

Команда создания пользователя читает пароль из стандартного ввода. Не передавайте пароль аргументом команды и не сохраняйте его в Git. Откройте http://127.0.0.1:4311/admin/.

Параметры находятся в приватном `data/config.php`, который возвращает PHP-массив:

```php
<?php
return [
    'origin' => 'https://example.com',
    'data_dir' => '/absolute/private/ursar-data',
];
```

Путь к конфигурации можно переопределить переменной `URSAR_CONFIG`. `origin` должен точно совпадать с адресом сайта: он используется для проверки источника запросов и настройки защищённых cookies.

## Файлы на Beget

Приложение располагается в `<папка-домена>/.ursar-app/`, рядом с `public_html`. Это сохраняет изоляцию Beget и наследует доступ только PHP-пользователя данного сайта. Каталог вне папки домена будет недоступен PHP из-за ограничений хостинга. В `public_html` находится только входной PHP-файл и ссылки на публичные ресурсы. База, конфигурация, секрет сеансов, резервные копии и загруженные изображения находятся в приватном `data/` приложения. Загруженные изображения выдаются контролируемым маршрутом `/media/`.

Публичные ресурсы имеют права 0755/0644. Серверные файлы используют 0750/0640 с унаследованным ACL Beget; база — 0660, её каталог и загрузки — 0770. Эти маски дают доступ владельцу и изолированному PHP-пользователю этого сайта; ACL основной группы и остальных клиентов доступа не даёт. Приватные данные не находятся в webroot. Не изменяйте ACL Beget вручную и не переносите приложение в общую папку аккаунта.

В панели Beget установлены PHP 8.4 и перенаправление HTTP → HTTPS. У домена должен быть действующий сертификат. `cms/public/.htaccess` направляет запросы страниц в PHP, запрещает листинг и доступ к служебным файлам.

Скрипт `scripts/deploy-beget.py` использует SFTP (библиотека Paramiko устанавливается отдельно в окружение публикации). Пароль SSH запрашивается скрыто. Проверка ключа SSH включена: сервер должен быть заранее известен в `~/.ssh/known_hosts`.

```sh
python3 scripts/deploy-beget.py \
  --host YOUR_ACCOUNT.beget.tech \
  --user YOUR_ACCOUNT \
  --app-dir /absolute/domain/.ursar-app \
  --webroot /absolute/domain/public_html \
  --origin https://example.com \
  --activate
```

Первое развёртывание дополнительно принимает `--initialize --access-file /private/local/access.txt`. Начальный пользователь — `info@ursar.ru`, пароль генерируется случайно и записывается только в этот локальный файл с правами 0600. Существующий файл не перезаписывается. При сбое после создания пользователя повторяйте публикацию без `--initialize`.

Скрипт сверяет SHA-256 файлов и передаёт только изменения, без архивов. Прерванную загрузку можно продолжить. Изменённые вне публикации серверные файлы не перезаписываются автоматически. Публикуйте готовую сборку: не запускайте новую сборку одновременно с загрузкой предыдущей.

## Обновления и данные

Исходные HTML в `site/` нужны для импорта дизайна и сборки шаблонов. После запуска редактируйте контент через админку. При обновлении кода существующие черновики, опубликованные версии, обращения и пользователи сохраняются. Новые исходные страницы и ресурсы импортируются при первом запросе после обновления сборки.

Идентификаторы текстовых полей связаны со структурой исходной разметки. Если менять структуру HTML вручную, нужно проверить перенос сохранённых правок и выполнить миграцию при изменении идентификаторов. Обычные обновления интерфейса и серверного кода не меняют поля.

## Резервные копии

```sh
php scripts/admin.php backup
```

Команда создаёт согласованную копию SQLite через Backup API в приватной папке `data/backups/`. Вместе с ней резервируйте `data/uploads/`, `data/secret` и конфигурацию через инструменты хостинга. Бэкап не следует помещать в `public_html` или GitHub. Автоматический график копирования этим приложением не создаётся.

Для восстановления остановите запись в приложение, сохраните текущую базу отдельной копией, замените базу нужным бэкапом и восстановите соответствующие загруженные файлы. Не заменяйте активную SQLite-базу при работающих запросах.

## Проверки

```sh
npm run build
npm test
python3 tests/check_site.py http://127.0.0.1:4311
```

`PHP_BIN` задаёт путь к PHP для тестов. Интеграционные тесты используют временную базу и проверяют вход, CSRF, роли, черновики и публикацию, конфликты версий, историю, товары, архив, загрузку и замену изображений, заявки, поиск, CSV, SEO и резервную копию. Проверка публичных ресурсов читает 33 страницы и их локальные изображения, стили, скрипты и шрифты.

## Границы двух версий

На Beget работают CMS и приём обращений. GitHub Pages остаётся статической демонстрацией с запретом индексации. Исходная серверная часть WordPress не восстановлена. Сохранённые страницы входа покупателей, бронирования, оформления заказа, платежей и отзывов не подключены к новому серверу: CMS предназначена для управления содержимым и обращениями.
